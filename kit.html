따라 만들기 키트
수업에 맞춘 플랫폼, 이렇게 만들었어요

이 키트는 완성된 플랫폼을 그대로 나눠 주는 자료가 아니에요. 우리 학교 선생님들이 수업 문제에서 출발해 도구를 함께 설계한 방법을 나눕니다. 정보 교과 전공이 아니어도, 학교 Google 계정과 생성형 AI의 도움으로 작은 것부터 시작할 수 있어요.

준비물: 학교 Google 계정 · Google 스프레드시트 · 생성형 AI 대화 도구첫 예시 따라 하기: 약 30~60분

출발점: 도구가 아니라 수업 문제

"어떤 에듀테크를 쓸까?"보다 "우리 학생에게 어떤 학습경험이 필요하고, AI·디지털은 그 안에서 어떤 역할을 해야 할까?"를 먼저 묻습니다.

이 키트가 권하는 방식

  • 교과 교사가 학습 문제와 학생 활동을 설계하고, 기능은 그다음에 정해요.
  • 학생이 먼저 생각하고 판단한 뒤 AI·디지털 결과를 보도록 배치해요.
  • 한 교과, 한 차시의 작은 도구부터 만들고 수업 뒤 고쳐요.

AID 수업 흐름

단계학생 / AI·디지털의 역할
A Assist교사 안내와 체험으로 진입 / 자료·체험 환경
I Independence예측·판단·초안을 먼저 수행 / 질문·힌트·비교·기록
D Deepen검토·수정·재구성·공유 / 검증 대상·공유 공간

6단계 따라 하기

한 번 만들고 끝내지 않고, 수업에서 확인한 뒤 다시 고치는 순환이에요.

  1. 학습 문제 정의

    성취기준과, 학생이 실제로 어려워하는 지점을 한 문장으로 적어요.

    예 학생들이 통계 그래프를 볼 때 그럴듯한 설명을 근거 없이 그대로 믿는다.

  2. 학생이 먼저 할 활동 설계

    도구 없이도 학생이 먼저 해야 할 관찰·예측·선택·작성을 AID 흐름으로 정해요.

    예 원자료 확인(A) → 모둠이 직접 도수분포표·그래프 작성(I) → AI 보고서의 주장을 수치로 검증(D)

  3. AI·디지털의 역할과 개입 시점 결정

    힌트·기록·측정·비교·검증 중 꼭 필요한 역할만 고르고, 언제 보여 줄지 정해요. 생성형 AI가 맞지 않으면 쓰지 않아도 돼요.

    예 AI 보고서는 학생이 그래프를 만든 뒤에만 열리고, 정답이 아니라 '틀렸을 수도 있는 주장'으로 제시한다.

  4. 생성형 AI와 함께 만들기

    1~3단계에서 정한 내용을 그대로 AI에게 설명하고 Code.gs와 Index.html을 받아요. 아래 요청 예시를 고쳐 쓰면 돼요.

  5. 수업에 적용하고 학습 증거 확인

    최초 생각, 수정본, 수정 이유, 측정 기록처럼 학생의 사고 과정이 남는지 봐요. 수업을 본 동료 교사의 의견도 함께 모아요.

  6. 설계 변경과 재적용

    기능을 늘리기보다, 발견한 학습 문제를 기준으로 활동 순서·AI 개입·교사 지원을 고쳐요. 고친 내용은 '바뀐 부분만' AI에게 요청해요.

AI에게 이렇게 요청했어요

배포하기

아래 예시 템플릿도 같은 순서로 올리면 돼요.

  1. 스프레드시트에서 Apps Script 열기

    새 Google 스프레드시트 → 확장 프로그램 → Apps Script

  2. 파일 붙여넣기

    Code.gs 내용을 붙여넣고, 파일 추가(+) → HTML → 이름을 Index로 만든 뒤 Index.html 내용을 붙여넣어요.

  3. setup 한 번 실행

    위쪽 함수 목록에서 setup을 골라 실행하고 권한을 승인해요. 스프레드시트에 시트가 생겼는지 확인해요.

  4. 웹 앱으로 배포

    배포 → 새 배포 → 유형: 웹 앱 → 실행 사용자: 나 → 액세스: 우리 학교 도메인의 사용자 → 배포. 나온 웹 앱 주소를 학생에게 안내해요.

  5. 고친 뒤에는 '새 버전'으로

    배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포. 이렇게 하면 주소가 바뀌지 않아요. '새 배포'를 누르면 주소가 바뀌어 QR과 안내 자료를 다시 만들어야 해요.

예시 템플릿

그대로 쓰기보다 우리 수업에 맞게 고쳐 쓰는 출발점이에요. '미리보기'는 저장되지 않는 체험 화면이에요.

A. 계획–집중–성찰 미니 플래너

학생이 오늘의 계획을 세우고, 타이머로 집중한 뒤, 잘된 점·어려운 점·다음 계획을 기록해요. 교사는 스프레드시트의 '반별 요약'에서 참여를 확인해요.

미리보기

B. 먼저 생각하고, AI 답과 비교하기

학생이 자기 생각을 저장해야 AI 참고 답변이 열려요. KEEP·USE·CHANGE 중 하나를 고르고 최종 생각과 고친 이유를 남겨요. AI 답변은 교사가 미리 만들어 넣으므로 API 키가 필요 없어요.

미리보기
B의 예시 질문에 들어 있는 AI 참고 답변은 일부러 틀린 부분을 담았어요. 섭씨온도를 그대로 비례식에 넣으면 안 되기 때문이에요. 학생이 그 오류를 찾아 '내 생각을 고침'이나 '일부 가져와 씀'을 고르고 이유를 쓰도록 설계했어요.

개인정보·접근 권한 점검표

학생이 쓰기 시작하기 전에 확인해요. 학교와 교육청의 개인정보 기준이 우선이에요.

  • 학생 이름 대신 반·번호·별칭처럼 꼭 필요한 최소 정보만 받는다.
  • 웹 앱 액세스는 '우리 학교 도메인의 사용자'로 제한하고, 스프레드시트는 담당 교사만 편집하게 공유한다.
  • 비밀번호·API 키·문서 ID를 코드에 직접 쓰지 않는다. 필요하면 Apps Script의 '스크립트 속성'에 넣는다.
  • 생성형 AI에 학생 실명이나 실제 응답을 보내지 않는다. 코드를 점검받을 때도 가상 데이터로 바꾼다.
  • 외부 서비스(예: Firebase)로 옮길 때는 데이터 보관 위치, 요금제와 사용료, 학교 승인 여부를 먼저 확인한다.
  • 학년이 끝나면 기록을 내려받아 보관 기준에 따라 정리하고, 다음 해 담당자에게 운영 방법을 넘긴다.

자주 막히는 곳

학생이 들어가지 못해요

배포의 '액세스' 설정을 확인하세요. 학생이 학교 계정으로 로그인했는지도 확인해요. 설정을 바꿨다면 '새 버전'으로 다시 배포해야 반영돼요.

코드를 고쳤는데 학생 화면이 그대로예요

저장만 해서는 반영되지 않아요. 배포 관리 → 수정 → 새 버전으로 배포하세요.

스프레드시트 열 이름을 바꿨더니 오류가 나요

코드는 열 순서와 이름을 기준으로 읽어요. 열을 바꾸고 싶으면 AI에게 '이 열을 추가해 줘'처럼 코드와 함께 고쳐 달라고 하세요.

여러 반이 동시에 쓰면 느려져요

우리 학교도 접속이 몰리는 플랫폼은 응답이 느려져 일부를 Firebase 기반으로 옮겼어요. 먼저 한 번에 읽고 쓰는 횟수를 줄여 보고, 옮길 때는 위 점검표를 다시 확인하세요.

AI가 만든 코드를 믿어도 될까요?

배포 전에 가상 데이터로 직접 눌러 보고, 위 '점검할 때' 요청으로 한 번 더 확인하세요. 학생에게 AI 결과를 검증하게 하듯 교사도 같은 습관을 가져요.

교육 목적이라면 이 키트와 예시 템플릿을 자유롭게 고쳐 쓰셔도 됩니다. 실제 학생 정보는 담겨 있지 않습니다.
